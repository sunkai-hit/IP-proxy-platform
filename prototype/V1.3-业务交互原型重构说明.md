# IP代理平台 V1.3 业务交互原型重构说明（2026-10-19）

## 一、问题与设计目标

上一版新增的“31项候选接口”和“36页/18案例”主要表现为清单；大量业务按钮仍依赖通用操作弹窗。这不能作为真正可操作的需求原型。

本轮依据 GitHub V1.3 36页面/18案例台账、详细需求第10章和第12章，重构默认入口：以真实业务对象为上下文，执行“查看关系→填写业务表单→资格预检→确认风险→本地状态回查”。所有动作仅操作当前浏览器内存，不能视作正式Vue应用、API联调或人工验收。

## 三、五条必须操作的走查路径

### 1. 多订单项五步开通
从首页进入五步开通，选择已付款订单 ORD-2417，其两个订单项为长效IP ×2、隧道 ×1；第二步显示三个独立实例。第三步核实外部采购期限，未核实应阻断。提交仅产生3条具有不同operationId的PENDING_REMOTE本地任务。同一订单重复提交仍只能保留原3条任务。远端执行/公网联网一直为UNKNOWN。

### 2. 独享公网出口冲突
选择 ORD-2419。203.0.113.18已由宽限服务 S-EX-02 保留，必须触发 EGRESS_IPV4_EXCLUSIVE_CONFLICT。改为203.0.113.82仅表示本地快照无已知占用，并不意味着产品组确认或真实联网成功。

### 3. 付款采购→平台反向代理→服务
外部采购先选择已付款订单，采购有效期覆盖订单销售期限；反向代理必须属于同客户采购和服务，代理期限不能超过采购期限。已有PUR-201短于S-EXT-03的客户期限，应阻断；可新建符合时限的模拟采购后重新核验，但仍不能显示网关成功。

### 4. 服务续费/宽限/释放
选择真实业务对象后发起续费；必须存在同客户已付款来源订单，防重复提交且上游采购不能过期。续费仅记PENDING_REMOTE，不修改旧到期。到期释放缺产品组真实回执必须阻断，不得将宽限IPv4回池。

### 5. 人工主备与专项保障
主备向导选择服务、备用候选、客户授权并展示出口/入口及监控影响。候选健康UNKNOWN或真实切换适配未签署，最终必须明确阻断。长效探测UNKNOWN不假恢复OPEN告警；停用机器人不能发送测试。

## 四、视觉及产品规则

- 左侧可折叠分组导航、顶部路径、KPI、主子表、详情抽屉、表单与步骤向导统一规划。
- 高危动作至少包含对象身份、字段、原因、预检、错误态与跨模块引用；不能仅弹“原型演示”通用提示。
- 管理面状态、远端任务、真实代理网络分别展示；UNKNOWN/Noop/Mock/畸形HTTP200不能显示成功或0流量。
- 域名使用.invalid；公网示例IP采用RFC文档保留网段；证件、密钥、Webhook均脱敏。
- 所有操作只改变浏览器内存。刷新页面重置，真实数据库、供应商、设备、代理网关均未调用。
- 原先31项接口参考与18案例核对，保留在 legacy.html，默认新首页右上可打开；该参考不再取代主要业务原型。

## 五、验证与尚未完成的工作

默认入口：prototype/index.html；主要逻辑：prototype/v13-business-app.js；样式：prototype/v13-business-app.css；旧版参考：prototype/legacy.html。

专项测试：prototype/tests/v13-business-app.test.cjs 和此前的 v13-workbench.test.cjs，由 .github/workflows/prototype-v13.yml 验证脚本语法、36页面导航、付款、独享排他、采购覆盖、代理归属、续费归属、释放阻断、幂等及本地表单操作。
