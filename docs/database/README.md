# IP代理管理平台数据库设计基线 V1.0

## 1. 设计目标

本设计对应已确认的工程基线：Vue 3 管理前端 + Java 21/Spring Boot 模块化单体 + PostgreSQL + Redis。数据库覆盖系统管理、客户、资源、产品、订单与服务、监控、日志、告警和小时统计，不包含“运营端反馈分支”中的余额、充值、退款和财务模块。

## 2. PostgreSQL约定

- PostgreSQL 16+。
- 主键统一使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`。
- 时间统一使用 `TIMESTAMPTZ`，应用层统一按配置时区展示。
- 核心业务表统一包含 `created_at / created_by / updated_at / updated_by / version / deleted`。
- 软删除字段 `deleted` 仅表示平台数据有效性；对接口同步资源不代表删除底层对象。
- 业务编码（如 `customer_code`、`order_no`、`service_no`）均设置唯一约束。
- 外部同步资源同时保存 `source_system + source_id`，并设置组合唯一约束。
- 核心业务状态使用 `VARCHAR` + `CHECK` 约束，由 Java Enum/状态机控制，不允许通过字典随意扩展。
- 通用可配置字典（客户类型、运营商、协议、认证方式等）以字典代码存储，由应用层按 `sys_dict_type/sys_dict_item` 校验，不建立大量跨类型字典外键。
- 所有金额若后续启用财务模块，统一使用 `NUMERIC(18,2)`；本版本仅订单金额使用此格式。
- JSON配置/快照使用 `JSONB`。

## 4. 核心约束

1. `res_ip` 不存在短效/长效类型；短效与长效由产品配置与资源策略实现。
2. 同一 `res_ip` 可属于多个逻辑资源池，通过 `res_pool_ip` 建立 N:M 关系。
3. 同一资源同一时刻只能存在一个有效独享占用；通过 `res_exclusive_allocation` 的部分唯一索引保证。
4. `svc_instance` 保存产品、套餐、资源策略和权益快照，避免后续主数据修改影响历史服务。
5. `svc_resource_binding` 统一表达服务与资源池/ROS/线路/IP等资源的绑定，不在 `svc_instance` 中堆叠多种资源ID。
6. `svc_credential` 不保存客户密码；Token仅保存哈希和掩码，VPN/外部密钥使用加密密文。
7. `biz_order` 与 `biz_order_item` 分离，一个订单可包含多个产品项。
8. 服务终止、资源释放、认证审批、Token重置等均属于业务命令，必须写 `sys_operation_log`。
9. 监控高频采样和使用日志按时间分区；小时统计由定时聚合任务生成。

## 5. 索引原则

- 主查询维度：状态、客户、服务、产品、资源对象、时间。
- 日志表统一至少包含 `(occurred_at)` 或等价时间索引，以及 `(service_id, occurred_at)`、`(customer_id, occurred_at)` 等常用组合索引。
- 同步资源统一包含 `(source_system, source_id)` 唯一索引。
- 所有外键列原则上建立索引。
- 软删除唯一约束采用 PostgreSQL 部分唯一索引（`WHERE deleted = FALSE`）。
