更新日期：2026-10-14。状态：第三轮Draft代码契约，未完成真实三方网络验收，也不替代原正式Word的全量修订。

## 业务对象与关联来源

|当前主单据|关联子表|GET路径（前缀 /api/admin/v1）|服务器双侧权限|数据证据|
|---|---|---|---|---|
|订单详情|实际生成服务或被续费原服务|/relations/orders/{id}/services|order:read 和 service:read|svc_instance.order_id 或 同客户RENEW目标，使用relation_type区分CREATED_FROM_ORDER与RENEWAL_TARGET|
|服务变更|已核实付款续费订单|/relations/services/{id}/paid-renewal-orders|service:read 和 order:read|只查询同服务、同客户、RENEW、PAID_CONFIRMED和PENDING_PROVISION订单；不再截取客户订单前200条后筛选|
|客户详情|客户订单|/relations/customers/{id}/orders|customer:read 和 order:read|biz_order.customer_id；包含续费原服务和付款核实状态|
|家宽线路详情|所属资源池|/relations/lines/{id}/pools|resource:read 和 resource:pool:read|res_pool_line.enabled、资源池主档|
|家宽线路详情|关联服务/客户|/relations/lines/{id}/services|resource:read 和 service:read|有效LINE服务绑定或未释放的svc_egress_claim.source_line_id，不读取过时的res_line.customer_id|
|资源池详情|使用中服务|/relations/pools/{id}/services|resource:pool:read 和 service:read|有效的svc_resource_binding(POOL)；**不推断**所有成员线路都被这个服务使用|
|供应商采购详情|平台代理列表|/relations/supplier-purchases/{id}/proxies|resource:purchase:read 和 resource:reverse-proxy:read|res_reverse_proxy.purchase_id|
|供应商采购详情|下游服务|/relations/supplier-purchases/{id}/services|resource:purchase:read 和 service:read|svc_instance.supplier_purchase_id或引用代理的采购关系|
|服务详情|有名称的资源绑定|/relations/services/{id}/bindings|service:read|svc_resource_binding与相关业务主档左连接，动态拨号IP不是固定出口承诺依据|

响应 `data` 为 `{items:[],source:"...",truncated:false,returned:0}`。最多200行；超过数量标识 `truncated=true`，页面不得将截断数量声称为所有历史数据。所有接口先验证主记录是否存在，之后只查询明示范围内的业务记录。不返回密钥、上游口令、授权原始JSON、全量变更JSON或完整错误堆栈。

## 页面交互准则
- 客户→订单/服务→服务绑定与出口→资源池/线路；供应商→采购→代理→服务两条主线具有真实链接。订单创建路径保留客户筛选，续费必须绑定已核实付款的原服务订单。
- 资源池显示“直接有效POOL绑定”的服务；线路显示“直接LINE绑定或未释放固定出口”的服务。二者统计口径不同，不能互相替换或相加。
- 外部供应商、采购和反代详情禁止原始字典逐字段/JSON展示；供应商和反代上游密钥后端不回传，采购成本/额度可选且不驱动后续业务。
- 父权限和子表权限同时要求；无子权限隐藏对应子表而非返回跨业务对象隐私；单一子表请求失败要提示“查询失败”，不能报“零个服务/无订单”。
- 绑定/网关ACTIVE、真实使用或固定IP“交付已验证”是不同概念。页面不得将有关联、已登记或Mock/Noop的ACK称作网络可用。

## 可复现验收
GitHub CI使用合成客户、订单、线路、来源池、服务，在 PostgreSQL Flyway全迁移后通过HTTP查询：
```
GET /api/admin/v1/relations/customers/{CID}/orders
GET /api/admin/v1/relations/lines/{L1}/pools
GET /api/admin/v1/relations/lines/{L1}/services
GET /api/admin/v1/relations/pools/{POOLID}/services
GET /api/admin/v1/relations/services/{SID}/bindings
```
验证客户至少一单、线路属于测试池、服务绑定名称对应主记录。采购/反代专属链目前具备后端接口和页面，但正式的实际供应商账号与网关结果仍须资源API/产品组签收；不会将本次页面/数据库查询当作完整网络闭环。

## 订单与服务的风险操作链

- 订单详情列表订单项与实际已创建服务，两种概念不能混淆；续费订单仅关联原服务为目标，不产出新服务实例。
- 续费支付必须由授权人员核实付款凭证，且已确认订单、套餐天数快照和同客户原服务校验通过；没有真实产品适配器verified回执时不得更新到期时刻。
- 服务列表所有高风险动作经 `/service-changes?serviceId=...&action=...` 统一预览；从已付款的续费订单可进入 `/service-changes?serviceId=...&renewalOrderId=...`，必须由后端重新验证该订单仍有资格执行。
- 到期+N×24h宽限按原合同快照，0天当时到期，已过宽限需要真正重新交付。Mock与Noop不能变为实际释放或恢复。
