# V1.2-R3｜真实接口联调能力签收清单（业务平台 ↔ IP资源API ↔ 五款代理产品）

状态：**发给外部组的可签署需求清单，非已获取的外部接口文档**。2026-10-14。
根据本分支源代码检查：ResourceAdapter 当前只有 Mock/Noop，实现不了真实设备控制；ServiceProvisionAdapter 仅定义 provision/release 和默认拒绝的 suspend/resume/renew；ReverseProxyAdapter 当前 Noop。**这里仅能说明业务平台仓库尚未实际连接，不推断另外两组是否已经开发了自己的接口。**

## 统一对接标准（所有执行类操作）
1. **系统来源**：接口实际提供方、测试地址、协议版本、认证/签名方式、权限范围、IP白名单及网络连通方式。
2. **资源稳定身份**：`sourceSystem + sourceId`不可被动态IPv4替代；每条线路须能关联ROS/CentOS，含最后更新时间/失效数据指示。
3. **能力声明**：每款产品逐项答复“支持/不支持/需开发”，不使用 UI 已经存在来推断真实接口支持。
4. **异步操作**：至少提供业务operationId、幂等请求键、接收/执行/成功/失败/不确定/补偿阶段；请求超时后必须能查单，不允许盲目重复执行。
5. **结果真实性**：成功回执须带执行对象、实际公网出口/平台入口、真实可用性证据、采样/完成时间；ACK/Mock/配置已保存一律不能等同可访问。
6. **服务生命周期**：开通/暂停/恢复/续费/切换/终止/释放必须说明究竟控制的是哪个真实入口/网关/认证服务，如何避免仅在平台数据库“改状态”。
7. **安全与审计**：凭证/上游Secret只在安全通道使用，列表/日志/回执脱敏；同客户/跨客户权限检查服务端完成。
8. **故障与回滚**：按网络不可达、超时、资源冲突、IP变化、认证失败、配置下发成功但探测失败分别提供真实错误码和补偿方案。

## 外部采购与反向代理执行方
- 供应商购买套餐、授权客户、到期/配额和真实使用量由授权接口明确；客户服务承诺期限不得长于可覆盖的有效采购期限。
- 反向代理的`apply/test/disable`必须提供`verified=true`且附验证时间、操作ID、真实网关状态；业务平台已在Draft分支阻断没有真实验证的“假ACTIVE/假DISABLED”。
- “客户服务解除绑定”与“取消上游购买”必须是不同动作；平台交付凭证与上游Secret隔离。

## 联调进入条件（DoR）
每组至少交付：
- 可访问的测试环境及账号权限（凭证通过安全渠道分发，不贴入GitHub Issues或对话）。
- OpenAPI/其他协议契约，包含示例：成功、资源不足、冲突、重复幂等、超时后查单、服务终止、回滚。
- 一组**可反复使用的脱敏测试数据**：稳定线路ID、地区运营商、ROS/CentOS、客户/服务、真实出口、期限与产品支持类型。
- 联系人、变更通知方式和谁负责确认“数据面真实成功”的测试证据。

## 联调签收规则
第一层：字段和状态对齐；第二层：Mock契约/异常路径通过；第三层：对真实测试网关执行开通→使用→停服→恢复/续费→释放→回查；第四层：并发/超时/切换/宽限/权限/审计。只有第三、四层具备真实证据时，才能把E2E矩阵相应行从“未运行”改为通过。
