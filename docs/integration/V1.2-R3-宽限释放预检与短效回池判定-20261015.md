# V1.2-R3 第八批｜宽限结束后的释放预检、共享判定及短效回池边界

> **当前交付：后端预检和受控查询接口。不是产品组真实释放或短效回池已完成。** 仅收敛既定V1.2-R3业务规则，仍复用V22任务表及占用表；不修改V1–V27历史迁移。

## 已完成的安全预检

已有`V12ExpiryTaskPlanner`在真实服务到期停服并完成`EXPIRED / GRACE_HELD`后，等到宽限截止，将该服务`expiry_phase`登记为`RELEASE_PENDING`，生成唯一`RELEASE`任务。第八批新增`ProductGraceReleaseInspector`检查这些任务，权限受业务平台`service:release`管理。

查询入口：`GET /api/admin/v1/v12/release-inspections/{operationKey}`。

关键检查：
1. 任务必须为`RELEASE`、`PRECHECK_BLOCKED`、无远端操作编号；服务必须属于长效或独享、当前`EXPIRED / RELEASE_PENDING`，自有交付、已超过按原到期时刻加 N×24 小时计算的宽限截止。
2. 每项该服务公网IPv4 claim需要具备原始合同截止一致的`hold_until_at`，且状态`GRACE_HELD`或`RELEASE_PENDING`，否则阻断。
3. 采用与现有数据库出口授权触发器一致的IPv4事务级 advisory lock，核查**同一公网IPv4所有其他未释放服务占用**，包括`RESERVED / ACTIVE / GRACE_HELD / RELEASE_PENDING`。未放行的历史独享占用（包括缺快照的旧记录）保持安全阻断。
4. 对每项claim生成判定（仅供联调审查，不作数据面凭证）：
   - `UNBIND_SERVICE_ONLY`：还有其他共享长效客户，**只允许产品组解绑当前已停服务授权，不允许把IP改短效或踢掉其他共享客户**。
   - `RETURN_TO_SHORT_AFTER_VERIFICATION`：已经没有其他受保护占用，才是**可进入转换的候选**。产品组仍须确认已撤销旧代理入口、实际转换到短效、短效健康探测成功、无其他端口继续暴露原长效/独享授权，并且代理短效池可见，才能真实释放业务IPv4占用。
5. 独享IP发现任何其他服务占用、历史独享数据缺证据、权益不完整或未到宽限截止，全部拒绝。短效池足够大不能替代严谨的隔离验证。

## 两组各自责任

业务平台：审查权益/订单/服务权限，记录`RELEASE`任务及原到期时间，区分只解绑服务和整个出口回短效、保留客户关联和证据、执行原子占用状态提交。

产品组：提供**实际资源**的原子排他保护、服务级解绑或全部模式转换、所有端口访问隔离、短效代理健康验证、幂等回执、设备端资源和用户数更新。

> 新增预检**没有**自动更新`svc_egress_claim=RELEASED`、`res_exclusive_allocation`、`svc_instance=RELEASED`，也不触发远端写操作。原因是共享资源回池必须由产品组实际核验，不能由管理数据库推断。

## 需要产品组联合签收的最少接口事实

- 服务级解绑与退出共享IP的真实执行回执（不会影响其他长效客户）。
- 最后一项占用解除后，产品组返回`resourceId / egressIpv4 / switchedToShort / shortPoolHealthy / allOldAccessRevoked / verifiedAt / operationId`，并提供同一操作编号的查单与重复请求幂等保证。
- 明确`RETURN_TO_SHORT`是否包含从长效/独享恢复设备短效代理能力的完整原子事务，以及失败回滚的短效健康验证。
- 业务平台在最终释放事务内重新核对所有其他claim和旧独享记录，再由验证证据驱动落账。**只做一次静态预检不足以构成真正授权**。

## 自动化核验

`ProductGraceReleaseInspectorTest` 覆盖共享他人占用、最后一项共享占用、独享全局排他、未到宽限、续费/状态变化、旧独享占用、holdUntil不匹配和从未真正回池等；`ProductGraceReleaseControllerTest`验证业务平台权限限制。CI仍执行原有后端、前端、Docker构建和烟测。
