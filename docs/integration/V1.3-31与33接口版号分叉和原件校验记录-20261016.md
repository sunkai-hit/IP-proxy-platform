## 2. 关键不兼容：F 编号语义发生漂移

**A01–E04 共 25 项**仍作为相同业务组别的候选基础；**F 系列编号在不同稿中重新分配，存在实际接口调用/开发误接风险**：

| 功能 | 当前 66 页／31 项 V1.0 编号（正在使用） | 97 页／33 项 V1.1 编号（待变更评审） |
|---|---|---|
| 线路拨号与公网 IPv4 变化日志 | **F01** | **F03** |
| DNS 解析检测与变更执行 | **F02** | **F04** |
| 反向代理配置及真实检测 | **F03** | **F05** |
| 真实短效 IP 授权提取/调度 | **F04** | **F06** |
| 设备/线路受控远程操作 | **F05** | **F07** |
| 真实代理日志与专项检测 | **F06** | **F08** |
| CentOS 实时监控明细 | 31 项 F 系列无独立编号（既有 A02/E03 等候选组合待确认） | **F01** 新独立接口 |
| ROS 实时监控与拨号摘要 | 31 项 F 系列无独立编号（既有 A02/A03/E03 等候选组合待确认） | **F02** 新独立接口 |

对同一个 `F04`，旧稿含义是**真实短效 IP 提取**，新稿是 **DNS 变更**；这是业务动作级别冲突，**不能简单合并字典或复用同一个接口编号**。

**暂行范围决定（延续当前已确认工程基线，不做新需求批准）**：

- V1.3 当前管理平台、[31 项接口签收矩阵](V1.3-31接口联合技术签收矩阵-20261016.md)、Issue #6/#10 继续以 **66 页/31 项** 的 ID 与含义追踪。两组及资源 API 组三方仍需对各自真实 Method/URI/字段签收。
- V1.1 97 页/33 项可作为**字段覆盖与可能的新增专项观测接口提案**；不能将 F01–F08 直接覆盖原 F01–F06。需经产品/技术联合确认最终接口总数、两项新增的责任归属及旧编号迁移/别名或重编号表，才可正式切换。
- CI `scripts/ci_v13_release_evidence_gate.py` 除 31 行 ID 数量外，新增对 **F01–F06 的名称、Method、候选路径**语义绑定。出现 33 项版重新编号必须显式评审并同步调整门禁，不能悄悄改变签收矩阵。
- **任何一份稿都未完成产品组三方真实接口签字**。不能从 97 页更多字段推断设备端已经具备这些能力。

## 3. 可执行的文档 P0 收口流程

1. **正式版号**：对需求详细/概要版 DOCX 原件统一文件名、封面、版本表、页眉页脚/图表标注；以实际完整 DOCX 渲染逐页复核 55/12 页，生成 SHA-256，记录修改前后对象清单和变更记录。绝不把改文件名当作正文已改。
2. **接口原件**：由有原始文件读取权限的成员将 **913,769 字节** 66 页 31 项 V1.0 Word **上传为本会话可下载附件**或提交到 GitHub 受控分支。校验实际 Word 页数/ID/F 项名称/字段/图表和 SHA-256，与当前 1,067,730 字节早期稿做差异后更新 README 的唯一正式入口。
3. **33 项稿处理**：确认是否替代 31 项候选接口；如果批准，先产出逐项旧→新 ID 映射、API 向后兼容方案及 36 页字段责任清单，再升级接口矩阵/SDK/自动化测试。没有正式选择时继续锁定 31 项。
4. **联合技术签署和真实网络验收**：对最终约定 ID/URI/Method/字段/样例/错误/重试/采样/幂等，由三方逐项签名；五类代理 18 项真实 E2E 独立验收。**Word 入库 ≠ 接口签署 ≠ 实际网络交付**。
