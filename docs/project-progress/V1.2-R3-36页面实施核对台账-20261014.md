## 本轮实际交付（可定位提交）
- `frontend/src/views/runtime/StatisticsView.vue`：分离CentOS、ROS、家宽/线路、来源池、客户、产品服务、外部供应商共七个入口；`V12StatisticsController`的资源池指标严格来自`res_pool_line → res_line`，当前快照与历史分开，跨池IP统计不相加。客户/产品/供应商小时统计增加无日志状态标注，避免将缺失代理数据当作0。
- `frontend/src/views/runtime/RuntimeLogView.vue`及`V12ExtendedLogController`：保留IP提取/使用/API，新增CentOS、ROS、拨号观测、IP变化、远程操作、域名、反向代理、操作审计共十一入口。新增八类按来源表查询，时间区间最多31天，默认7天，按权限控制，去掉原始敏感JSON及完整堆栈；操作审计需额外`system:operation-log:read`。
- `InfrastructureStatisticsRepository.dashboard()`与`DashboardView.vue`：按服务管理ACTIVE/真实验证阶段拆开，补到期停服、宽限、释放阻塞、未解决任务和上游采购将到期指标；不展示原先五步全部打勾的静态“成功”流程。

## 2026-10-14 第五批：主子表和跨单据导航整改

- `V12BusinessRelationsController` 提供7个只读关联接口，分别是客户订单、线路资源池、线路服务/出口占用、池直接服务绑定、采购下代理、采购使用服务以及服务资源绑定对象名称。每条接口均校验主记录存在以及所需的双业务权限，避免因父对象权限而间接读到无权查看的业务子表。返回最近200条和是否截断，不将日志、原始凭证或技术JSON发给页面。
- 业务路径贯通：客户详情→订单/服务→服务资源/历史→线路/资源池；供应商详情→采购→反向代理→客户服务；采购来源订单核实状态另设链接。数据来自明确的订单ID、服务绑定、池线路成员和采购代理关系，不通过旧的线路customer_id或当前动态IP猜客户。
- 采购和代理详情由原先循环展示原始对象/JSON改为结构化业务字段和两级业务子表；上游/平台加密密钥不回显，账号在页面掩码，代理动作按服务端权限及真实适配器核验。
- 受测范围仅管理面：关联接口PostgreSQL+Mock烟测、前后端构建和Docker。真实资源API、五类产品及网关连通/停服/回收仍未进入实测签收，不能据此认定正式业务闭环完成。
