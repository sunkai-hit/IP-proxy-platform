## 本轮贯通核查补充（订单／服务／资源／权限；2026-10-15）

**已实修、非新需求**：

- 后端`V12ServiceLifecycleService.provisionPreview`对长效IP的交付建议已从旧“长效线路固定绑定”修正为“优先复用已验证、有容量的长效共享出口；否则经产品组确认短效转长效”；CI通过真实HTTP的长效新购订单预览校验该口径（不触发产品写）。
- `ServiceChangeView`续费必须有`service:renew`，暂停／恢复／终止必须有`service:status`，且统一需要`service:change`；非续费动作不再请求仅续费才需的已付款订单；`ServiceDetailView`不再向无对应动作权限的用户展示可能不可执行的变更入口。
- `OrderServiceController.detail`按`service:credential:read`将凭证子表从HTTP响应中移除，仅前端隐藏页签不算权限控制；`V12ServiceMapper.credentials`不再返回任意扩展`metadata`，保留账号和密钥掩码等必要展示字段；回归测试验证普通service:read不可读取。
- 新增`scripts/ci_v13_api_contract_gate.py`逐项比对订单、服务、资源、关系、到期任务等关键前端GET/POST与后端Spring映射，覆盖经Vue页面直接发起的只读任务接口；需要签收的高危产品写接口按“后端存在、前端不开放”处理。动态API和非核心路由只输出待复核项，**不把静态匹配视为浏览器验收**。
- 现有GitHub Actions继续对真实PostgreSQL做多订单项实例主子关系、原服务续费引用、付款前置、独享IPv4冲突、长效共享释放及宽限记录校验。

**未闭环**：36项页面尚未全部完成浏览器动作点验；独享/长效真实出网及设备侧迁移、服务真实停服/回池仍需产品组测试环境签收。**不得以本轮CI成功代替真实数据面验收。**
