### A 阶段 UI-05 / UI-06 可靠性与高危账号动作（本批待 CI）

- **UI-06 资源概览**：原页面 `load()` 只有 `finally`，请求失败会保留上一次资源计数并产生未处理异常；“最近同步任务”的“查看全部”仍跳转未注册的 `/sync-tasks`，与 V1.3 的36项已批准导航不一致。本批清理旧指标、显式失败/重试，保留当前页面合法的只读记录，不擅自恢复第37个页面。
- **UI-05 客户账号**：原页面顺序拉取选项、客户、账号列表，任一选项查询失败会使账号列表整体不可见；账号读取出错也缺乏清旧状态与恢复入口。密码重置分两段弹窗，冻结/恢复/停用等写操作未在确认期间冻结账号身份、状态或设置单次锁，存在误操作/重复操作风险。本批采用独立选项错误与列表错误、确认快照和状态/权限再验证，账号写回执仅表示管理端已返回。
- **回归结果**：[PR #34](https://github.com/sunkai-hit/IP-proxy-platform/pull/34) 最终head `b771f13eca80db5e19e0d223633e076b3632d774`，[PR CI #38895691582](https://github.com/sunkai-hit/IP-proxy-platform/actions/runs/38895691582) 86/86 Chromium + 3/3构建成功，已合并 `main` SHA `b8768e258705862b86911b72c292d4b1160b6864`。4项浏览器专项涵盖资源概览503失效/恢复、账号列表503防旧记录+重试、选项503不得创建账号、冻结取消不发POST。**未取得合并后main独立CI与人工业务签收，不能宣布 UI-05/06 或 A 全部验收完成。**
- **仍需人工点验**：UI-05 密钥权限与客户授权主子表、账号实际创建/密码轮换审计、多角色实际操作；UI-06 自有/供应商数据来源、时间戳和新鲜度；业务负责人逐项签收。B/C 真实代理、旧同步任务页面恢复均不在本批范围。

### A 阶段 UI-11 独享公网IPv4历史占用核查可靠性（PR #35 已合并，PR CI 已验证）

- **现存工程缺陷**：历史占用列表 `resourceApi.exclusive` 查询失败只有 `finally`，会保留上一次历史IP/出口claim内容且未明确错误；详情抽屉 `exclusiveDetail(id)` 没有锁定所选ID与响应顺序，较慢旧详情可能污染当前核对视图。
- **修复范围**：按查询代次清空过期列表；失败告警并允许重新查询，当前状态缺失必须显示未知；详情抽屉按记录 ID/请求版本关联，响应ID不一致或服务端503均拒绝呈现旧合同/出口；关闭抽屉、刷新列表时失效旧请求；不增加解锁、释放或复卖按钮。
- **专项回归（新增4项 Chromium + Spring/PostgreSQL 管理面回归；受控HTTP注入）**：①列表503防陈旧占用并回真实后台；②详情返回其他ID时拒绝，正确数据才能重试展示；③关闭A详情并打开B时A慢响应不能串详情；④详情503时不给服务出口/任务详情操作。
- **最新验证**：[PR #35](https://github.com/sunkai-hit/IP-proxy-platform/pull/35) 最终head `ea9c94fdf36cc2e2a07c87356091de08a74947b1`，[CI #38897397935](https://github.com/sunkai-hit/IP-proxy-platform/actions/runs/38897397935) **104/104 Java、90/90 Chromium、前端/后端/Docker 3/3 全部成功**；合并 `main` SHA `a111613f355f5bcd46dc26f2a52e58cee6b5151c`。这只是 PR 最终head的真实验证，**合并后main独立CI尚未拿到可核实结果**；真实独享公网IPv4归属、回收与存量迁移仍属于外部B/C/上线前独立签收；UI-11逐字段、多角色、真实证据的人为签收仍未完成。

### A 阶段 UI-34/35：后台权限授权与审计的管理面安全收敛（PR #36 已合并，PR CI 已验证）

- **确凿现存问题**：系统管理原页面每次打开就 `Promise.all` 并发加载用户、角色、权限、字典、参数、登录和操作日志，即使当前角色仅拥有其中一项读取权限，也会调用无权限接口；原角色勾选 `selectRole` 无异步对象隔离，A角色慢返回可能覆盖B角色已选权限；读取失败后既不标未知，也没有防止“空勾选保存”的锁。高危授权原 `saveRolePermissions` 直接以可变 `selectedRole` 提交，可能错授权；后台密码重置缺少对象/权限冻结。登录与操作审计 503 也未清旧记录和明确未知。

### A2 续费/生命周期变更与到期扫描的管理面确认安全（PR #33 已合并、主分支已验证）

- **实际缺陷一（UI-25）**：服务生命周期表单提交后，如果用户切换到另一服务或动作，旧请求返回的成功/失败摘要仍可能显示在新服务下；变更结果目前按管理面状态展示，不能被误认为真实产品状态。现冻结动作与服务身份，异步响应只允许写回原服务上下文；切换服务或动作清除旧结果，过时请求只能提示回原服务/任务审计核对。
- **实际缺陷二（UI-25）**：终止接口可能 HTTP 200 但业务体为 `status=FAILED` 或 `RELEASE_BLOCKED`，原页面始终弹管理请求成功提示。现单独识别 FAILED/PARTIAL_SUCCESS/RELEASE_BLOCKED，明确失败或未核验状态，不能认定网络停服/释放成功，并要求独立回查服务任务。
- **实际缺陷三（UI-26）**：到期任务扫描此前在确认弹窗等待时尚未标记忙态，允许重复发起确认；取消弹窗是未经捕获的 Promise 拒绝。现在进入确认即设置 single-flight，用户取消不提交，最终提交时重新核对 `service:release` 权限，扫描未知结果不得继承上一次显示值。
- **回归证据**：[PR #33](https://github.com/sunkai-hit/IP-proxy-platform/pull/33) 最终 [CI #38879592395](https://github.com/sunkai-hit/IP-proxy-platform/actions/runs/38879592395) **82/82 Chromium + 3/3 全绿**，并且合并提交 `a9769a29f74b39e0945481d55e3c6b11ef8633c5` 的独立 [main CI #38880107509](https://github.com/sunkai-hit/IP-proxy-platform/actions/runs/38880107509) **82/82 + 3/3 全绿**。新增3项 Chromium 测试分别在受控 HTTP 回执下验证终止失败态、跨服务晚返回隔离和扫描确认取消/单飞，不向真实代理设备、支付或供应商发请求。完整正常/异常续费、宽限与共享 IP 释放的产品组真实执行和多角色人工签收仍未完成；真实网络集成 B/C 暂缓。
