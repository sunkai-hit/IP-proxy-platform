## 1. 已锁定的两组职责

| 对象 | 业务平台组 | 代理产品组 |

**现行业务规则：**短效IP被提取后仍在池内，显示使用人数；短效IP不保证固定；转换成长效/独享时原短效用户转移至其他短效代理（优先负载较低），已迁移的用户不需迁回。若迁移容量不足，应拒绝转换；失败时恢复原短效能力。转成长效/独享后不得再向短效客户提供该IPv4。长效允许多个客户共享；独享按实际公网出口IPv4全球唯一且同客户不同独享服务也不复用。

## 3. 长效IP分配最小决策契约（已确认业务，产品组尚需签收能力）

1. 业务平台验证订单已付款、服务和客户归属、套餐地区/运营商/协议、服务有效期。
2. 产品组返回**当前可用长效共享出口候选**，附 `resourceId / egressIpv4 / capacity / used / health / version / sampledAt`。过滤不满足能力、容量、客户授权和独享排他的项。
3. 有合格长效共享出口时，按**可验证的剩余容量及健康度**排序，优先复用；业务平台为新增服务独立登记合同、权限与引用。产品组执行原子占用；并发容量变化必须重新选取。
4. 没有合格长效出口时，产品组在短效池**原子预占**可转换资源 → 容量预检 → 迁移当前短效用户 → 所有旧短效入口撤销 → 转换长效 → 实际出口和入口验证。
5. 转换失败执行产品组回滚恢复短效能力；已迁移用户不强制回迁，保留幂等任务和审计。**不依赖预检快照占用**。
6. 任一长效客户到期仅撤销自身授权；仍有其他有效或宽限保留的长效服务时不得回短效池。最后一个占用完成真实释放、排他检查及健康验证后才允许回池。
7. 已有长效服务的固定出口若不变，可复用；**不能为了均衡负载悄悄迁移该长效客户的IPv4**。

必须产品组确认：容量计量单位与阈值、固定出口保障、资源/出口稳定ID、短效运行时会话切换语义、预占TTL与超时、操作查单、真实可用性测试。

## 6. 第三批：业务平台统一权限与产品组最小安全契约（2026-10-15）

**已提交代码（尚需以最新提交CI终态为准）：**
- 新增 `POST /business/v1/authorizations/check`：与两组接口草案路径一致。产品组只有在配置 `PRODUCT_INTEGRATION_BEARER_TOKEN`（至少32字符）且请求提供匹配Bearer Token时才能请求，默认不配置即403，其他管理JWT不能替代产品组凭证。
- 现阶段只支持 `SHORT_EXTRACT` **非扣额预检**，且须同客户账号与服务绑定、当前真实交付阶段为`VERIFIED`、授权授予未撤销、订单已核实付款（订单来源服务）、有效期/额度/频率满足。返回短期有效的`ALLOW`或`DENY`。其它`CONNECT/PROVISION/RENEW/... `统一`ACTION_NOT_SUPPORTED`，避免越权默认放行。
- 接口参数`subjectId`现定义为业务平台`customer_account.id`的字符串形式；`serviceId`同`svc_instance.id`。这是当前临时签收字段映射，不要求产品组设备侧自行判断客户权限。
- 修复旧 `OpenApiService.issueToken`：不允许通过重新登录自动把 REVOKED / DISABLED 授权重新变为ACTIVE；并在数据库令牌轮换时用`WHERE status='ACTIVE'`再次核对，阻断并发撤销被覆盖。
- 新增安全回归测试：未配置/无效产品密钥、撤销授权、未付款、模拟交付、无客户权限、超配额、超频次、其他动作不继承短效权限。
- 没有为任何客户扣减额度，没有新增正式数据面接口，不声称产品端已经执行授权。

**仍待双方签收：**产品组到平台的网络准入机制（后续生产必须加mTLS/网络限制、密钥轮换）；产品组对实际客户身份的证明；每次资源分发最终扣额与计量的原子执行；五款产品除短效提取以外的授权动作；授权撤销向产品组推送和实际停连回执。这些未完成时不得把非扣额预检当成正式资源交付许可。
