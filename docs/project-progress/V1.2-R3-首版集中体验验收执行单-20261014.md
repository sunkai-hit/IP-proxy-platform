## 第一版集中验收操作顺序

对每条业务链统一执行这六项，不再单独开新设计工作：

1. **列表**：按编号/名称/状态/客户筛选并恢复，关注无数据、无权限、分页。
2. **详情**：主记录和当前业务状态正确，真实采样有来源和时间，敏感凭证不可回显。
3. **子表**：订单项与服务实例、线路与池成员、采购与代理、监控与通知的主子归属一致，不以裸ID/原始JSON代替业务。
4. **关联跳转**：从业务对象发起合法新建、预选当前客户与原服务，返回时上下文不丢失。
5. **合法/非法操作**：强制付款先行；0宽限明确确认；人工切换、停服、回收未真实验证时不得假成功；确认原因与权限一致。
6. **结果回查**：操作后直接进入已产生单据详情，失败不丢原服务期限、客户固定出口与已有绑定；异步任务/回执按真实来源查看。

## 第十三批后续：第二条主线合同与续费集中验收

- **合同来源**：LONG_IP / EXCLUSIVE_IP 按服务`grace_days_snapshot`和`grace_until_at`判定原权益，不从当前套餐的`grace_days`推断历史合同；普通产品不套用固定出口宽限。
- **套餐修改不回写旧权益**：合成一个宽限为0天的已建长效服务，将所属套餐改为3天。检查套餐为3天但原服务及套餐服务子表仍记录0天。
- **付款前拦截**：超过原宽限的固定IP服务直接拒绝创建原服务`RENEW`订单，错误码`RENEW_OUTSIDE_GRACE`，要求新购并重新真实交付。历史宽限快照缺失时也不能自动补猜。
- **执行前再校验**：宽限内创建、确认、模拟核实付款的续费单，Mock适配器必须拒绝真实续费；若付款后实际跨过宽限截止，执行时还要返回`RENEW_OUTSIDE_GRACE`，不得更新服务到期、合同快照或将订单完成。
- **运营表单**：续费天数只读且来自订单的`package_snapshot.service_days`，快照读取失败不可用默认30天继续提交；显示原合同宽限及UTC新到期试算、已付款订单入口。实际成功以服务端核验和真实适配器回执为准。

结论只针对**管理面数据、API和编译验收**；人工界面多角色操作及五类产品真实续费/固定公网出口保持，仍需要对应外部技术组证据。对“宽限外”订单的客户已支付历史异常须人工处理，不自动代客退款或迁移合同。

## 第十五批：第三条资源链管理面集中核对

- **1:1与职责**：ROS详情增加所属CentOS业务名称/跳转；线路能直接进入ROS与CentOS。CentOS负责B/C段管理统计，ROS只保留拨号上报，不能把拨号IP当成客户合同固定出口。
- **敏感字段**：线路列表、详情从后端读模型中删除`broadband_account`明文，后端只按当前原值构造掩码`broadband_account_mask`；前端只读取掩码。数据库原资源账号不被此只读整改覆盖或变更。
- **来源池成员**：CI将一条线路加入两个不同来源池，核对`/relations/lines/{id}/pools`返回两个真实成员记录。不按当前公网拨号IP反推出所属客户，也不将跨池服务总数简单相加。
- **在用保护**：资源池移出/整体替换成员前核对直接绑定该池的服务与未释放固定出口；不能移出仍承担固定出口的线路，不能清空有未终止服务的来源池。失败后成员状态不变，必须通过服务真实停用/回收后再操作。
- **独享IPv4全局排他**：CI以同客户两条不同服务构造同一个合成保留公网IPv4，第二条占用必须被数据库拒绝，不能因客户相同而允许复用。此项验证的是数据库占用约束，不是实际上游已分配出口。
- **验收边界**：上述是合成资源和业务数据库检查。真实CentOS/ROS在线上报、拨号数据真实性、固定出口验证、实际客户访问与资源回收必须按现有E2E01—18及历史存量迁移签收；没有真实证据不得标为完成。

## 第十六批｜第四条业务链采购与代理配置闭环

本批延续原调研口径：无平台钱包/支付通道、无自动采购；供应商成本及剩余额度仅可选记录，不推导自动扣减。

- **收款先行**：只有来源`biz_order.payment_status=PAID_CONFIRMED`、客户归属一致且订单未取消，才可以通过API登记客户专属采购。库存/旧采购可保留只读记录，但没有明确的客户专属采购与真实付款来源时，禁止直接转成客户平台代理。
- **客户归属锁定**：代理必须对应唯一客户的有效采购；代理可关联已存在且同客户、未终止的服务，不允许跨客户服务ID。供应商已过期/有效期不明不能新建代理；来源采购到期早于所挂服务到期则阻断，等待上游采购核对。修改代理不能用传入的采购或客户ID改变归属。
- **已有界面操作闭环**：采购详情增加“基于此采购登记代理”入口，反向代理页增加已有API对应的配置表单，选专属采购后自动带客户并只列同客户服务；创建后直接进入新代理详情。页面与API都明确“登记配置非网络交付”。
- **真实执行仍受控**：Noop或仅传输ACK不得把代理状态变为真实ACTIVE，也不得称成功；原来适配器真实验证门槛保持不变。管理面列表/详情只是实际关联与状态快照。
- **回归测试证据范围**：当前CI新增客户错订单采购拒绝、已付款采购可登记且成本额度为空、库存被拒直接挂客户代理、采购客户不符拒绝、服务跨客户拒绝、合法配置登记及采购代理子表回查、Noop应用拒绝且原状态仍PENDING。CI生成的是模拟付款核对与采购登记记录，不是实际向供应商下单或代理连通。

**阶段结论**：首版第四条链已完成管理面流程与正反测试设计；浏览器多角色互动、真实供应商采购与反向代理网关、上下游服务期限和真实停用回执仍须签收。继续Draft，不以HTTP 200冒认外部交付。
