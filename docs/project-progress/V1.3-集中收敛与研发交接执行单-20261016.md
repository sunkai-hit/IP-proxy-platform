## 3. 需要外部产品组与资源 API 组签收的阻塞

产品组必须实测：A04 短效真实使用人数、A05 长效剩余共享容量；B01–B05 预检、原子预占、短效会话迁移、长/独享转换和失败恢复；C01–C07 网络服务开通/查单/停复服/终止/最终短效回池；D01–D03 权益审核和撤销；E01–E04 采样、真实使用量和对账；F01–F06 增补的日志、设备、DNS、反代和提取能力。不能以已写好的代码映射代替签约与设备回执。

资源 API 组明确 CentOS/ROS/线路稳定 ID、来源时间、拨号和设备操作能力、资源变动事件。三组协作并不改变原来的「CentOS 管理+B/C，ROS 仅拨号；业务平台保留唯一客户权益授权；代理产品组负责真实连接与容量占用」的边界。

## 4. 五条业务链的退出证据

1. **客户—订单—开通—服务**：新购 2 项 3 实例、付款前拒绝、重复下发去重、订单项与实际服务子表正确；真实交付另外验收。
2. **套餐—续费—宽限—释放**：原合同权益不随新套餐变化；越过宽限不能原服务续期；到期停服先有真实证据，未释放不能解占用。
3. **CentOS—ROS—线路—来源池—公网出口**：稳定来源标识/多池成员、固定公网出口与动态 IP 区分、独享同客户跨服务也排他、共享最后一个客户退出后才可回池。
4. **已付款—供应商采购—反向代理—服务**：同客户及期限约束、成本额度可选、采购登记不等于实际购买或远端配置。
5. **长效服务—监控—机器人—告警—通知**：客户多机器人、真实探测时间与通知回执、人工归档不表示网络恢复。

## 5. 收口纪律

- 每个 PR 记录最终 SHA、前后端构建、Flyway、实际 PostgreSQL 负测、真实浏览器覆盖、外部设备 E2E 的不同证据等级。
- 管理平台验收与网络产品验收分开；可以交接 A，不应以 B/C 未签为由重做 A；但不能在未签 C 时宣布生产上线。
- 对缺失真实接口的地方继续安全拒绝，不写假数据、不扩大范围、不改旧 Flyway、不因为 UI 可以点击就开启真实写开关。
- 最新接口合同正式提交后，更新 31 项矩阵与代码/SDK 映射；确实不支持的接口记录替代或延期计划，不凭候选 URI 猜想已经部署。

## 6. main 集成后首批 P0 工程整改（PR #12；2026-10-16）

- **已合并的前置基线**：PR #11 已于 2026-10-16 合并至 `main`（`4ef2f163`）；旧 #1/#2/#3 PR 已收敛，现有工程不应从旧 V1.2 分支继续开发。合并后的主分支 CI #38829057821 通过。
- **短效 Open API 安全闸**：仍未收到产品组的真实短效授权分发/容量回执，`OpenApiService.extract` 不得再默认从管理快照 `res_pool_ip/res_ip` 向客户返回看似可用的 IP。新增 `LEGACY_SHORT_EXTRACT_ENABLED=false` 默认拒绝；仅在显式开启且 Spring `m6-mock` 活跃的合成测试环境才执行旧 SQL。生产既有 Token/服务权限不会因该开关被视为真正交付权益。统一授权的生产联调路线仍为产品组权威 F04/D01 候选接口，尚未实际接通。
- **旧 Open API 跨客户关联核对**：`open_access_grant` 查询必须同时校验账号和服务实例属于同一 `customer_id`，阻止仅依赖历史授权行的意外跨客户读路径。
- **资源详情/列表多场景体验**：CentOS/ROS/线路共用的详情 Vue 组件新增路由切换重加载、并发旧请求版本校验、失败状态与重试；资源列表新增失败状态/重试/旧请求保护。IP 变化历史、运维日志、来源池与服务关联读取失败分别显示原因，不得把网络失败显示为正常空数据。
- **实际验证手段**：`OpenApiLegacyExtractionGateTest`、`OpenApiMapperGuardTest`、真实后端 HTTP 旧资源分发默认拦截、Playwright 浏览器的线路→ROS→CentOS 复用组件导航、接口 500/503 错误呈现与恢复、无权限角色直调资源接口。此处只说明**测试已编写并纳入 GitHub CI**，以 PR #12 最新 SHA 的 Actions 终态为验收结果，不能把未运行/失败测试填成通过。
- **保留发布边界**：这些更改仅增强管理平台的失败可见性与权限/资源安全，不证明真实代理已连通。31 项接口技术签约和 18 项网络 E2E 仍依赖产品组、资源 API 组测试环境，不重写 V1–V27 历史 Flyway。
