- 业务平台：订单、状态、权限、资源/出口锁、生命周期任务、日志及运营页面；Mock只可用于契约测试。

## 技术测试门槛
1. migration V22须在干净 PostgreSQL 和含V1–V21真实模拟历史数据环境验证前滚、约束、回滚预案；历史独享占用未迁移则停止正式切流。
2. 前端与原型至少验证新购多项多实例、冲突、宽限、人工切换、外部期限、异步失败、只读权限七组交互。
3. API contract必须通过OpenAPI格式校验，增量路径不能替代已有接口；返回的状态来源/刷新时间/错误码必须真实。
4. GitHub CI前后端和迁移成功仅算**工程门槛**；尚不能代替网络真实验证。
5. 合并前须留下可复核的测试命令、提交SHA、CI结果、测试样本（脱敏）和负责组签收。
