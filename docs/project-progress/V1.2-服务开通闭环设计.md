# V1.2 服务开通闭环设计与实现说明

版本基线：《IP代理管理平台需求说明书（V1.2-服务开通闭环修订版）》第8章。本文是开发与原型对照说明，不替代正式需求文档。

## 业务对象与主流程
- 订单记录客户、产品、套餐、服务数量、周期与交易金额；订单确认后状态为 `PENDING_PROVISION`。
- 普通服务开通只处理待开通订单。订单列表/详情的“开通”仅跳转向导，不能跳过预检直接执行。
- 开通向导五步：订单确认（只读）→交付配置（逐订单项）→资源预检→开通确认（原因）→开通结果（服务号、实际资源、一次性凭证）。
- 订单项支持自有交付 `SELF_OWNED` 或外部反向代理 `EXTERNAL_PROXY`，一个订单可以混合多订单项/多交付方式。
- 每个外部服务实例绑定一个明确且当前未占用的反向代理；供应商采购单由代理反向查得，不要求运营重复输入ID。
- 管理员特殊手工开通独立权限 `service:provision:manual`，不再作为普通页面默认表单。

## 产品开通差异
| 产品 | 自有资源开通 |
|---|---|
| 短效IP | 校验SHARED共享线路池；服务绑定资源池及内置规则，IP提取时动态选线 |
| 长效IP | 校验LONG线路、出口IP和容量；固定绑定推荐线路 |
| 独享IP | 根据套餐`ip_count`或产品默认`resource_count_default`确定数量，从不在活跃资源池且无服务/独享占用的在线线路中分配；行锁+已有唯一索引防止重复独享 |
| VPN | 需实际VPN数据面适配器；缺失时开通失败，不可假称已交付 |
| 隧道 | 需实际隧道数据面适配器；缺失时开通失败，不构造隧道型资源池 |

外部反向代理交付为独立交付方式，不是新的产品类型。需客户一致、代理`ACTIVE`、采购`ACTIVE`、未绑定服务且覆盖服务有效期。

## 后端契约
- `GET /api/admin/v1/orders/{id}/provision-preview`：读取订单只读字段、订单项、当前可交付的反向代理和自有资源预检信息。预检不保留资源锁。
- `POST /api/admin/v1/orders/{id}/provision`：
  ```json
  {
    "reason":"客户合同确认，执行开通",
    "plans":[
      {"orderItemId":123,"deliveryMode":"SELF_OWNED","reverseProxyIds":[]},
      {"orderItemId":124,"deliveryMode":"EXTERNAL_PROXY","reverseProxyIds":[1001,1002]}
    ]
  }
  ```
- `plans`必须覆盖订单的全部订单项；外部代理ID数量必须等于该订单项的`service_count`，且整个请求不能复用代理ID。
- 事务内锁定订单并防重，锁定反向代理或独享候选线路，重检业务归属和状态；所有要求的服务均成功后订单才变更为`PROVISIONED`。
- `POST /api/admin/v1/services/provision`仅管理员/特权用户可执行并要求操作原因。
- `oneTimeCredential`仅代表实际新签发的服务凭证。外部平台代理已有认证时不额外生成未配置到平台代理的“虚假密钥”；只有白名单认证时不强制签发Token。

## 交付能力边界与后续联调
- 现有 `NoopServiceProvisionAdapter` 对短效/长效/独享返回**管理面逻辑开通**结果，对VPN/隧道拒绝实际开通。响应 `deliveryStage` 为 `MANAGEMENT_ONLY` 时，运营必须看到“仅管理面开通”，不能宣称网络代理已真实可用。
- 反向代理配置需由真实适配器下发且状态为`ACTIVE`才允许绑定客户服务；Noop适配器的待配置状态不视为已交付。
- 数据面网络设备的跨系统回滚、真实端到端连通性、计费扣减、产品地区/运营商策略优先级的专项算法仍以实际适配器和业务联调为准，不应伪造测试成功。
- 开通失败应保持订单`PENDING_PROVISION`；与外部设备交互存在不可自动回滚的场景时，需要独立补偿与重试机制并记录审计，不能仅依赖本地数据库事务。

## 验收重点
1. 多订单项、自有+外部混合方案能够逐项填写并准确创建服务数；
2. 外部采购失效/代理被占/客户不匹配/期限不足必须拒绝；
3. 同一订单并发/重复提交不能重复创建服务；
4. 独享套餐需要N条时，实际分配恰为N条，不足则拒绝而不产生部分占用；
5. VPN/隧道数据面未配置时不会虚报成功；
6. 原型与正式页均展示业务名称，不能要求运营录入技术ID或阅读调试JSON；
7. 权限：普通服务开通走订单，管理员手工开通和外部代理授权独立校验。
