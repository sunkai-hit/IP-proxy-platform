# V1.2｜第二轮设计收敛：全模块页面总表与统一交互规范

**状态**：第二轮页面/字段/交互**评审稿**，不是已发布正式需求；日期：2026-10-14。  
**基线**：[V1.2正式Word](../requirements/IP代理管理平台需求说明书-V1.2.docx) + [第一轮P0设计稿](V1.2-P0-核心业务闭环设计收敛-第一轮评审稿.md) + [竞品报告](../research/competitors/caihong-2026-10-14/report.md) + [用户业务确认](../research/competitors/caihong-2026-10-14/business-confirmations.md)。  
**本轮经用户明确批准的三项原则**：①独享IP按**公网出口IPv4跨客户排他**（不同端口也不可由他客共享）；②长效与独享套餐**分别配置续费宽限天数**，不得全局写死；③**当前只有人工主备切换**，不引入自动切换。  
**范围**：设计页面、列表字段、查询、表单、详情主子关系、操作状态、权限与验证；不修改业务代码、交互原型、正式Word或API契约。第一轮尚未确认的接口能力/个别参数继续保留“待确认”标签。

## 1. 总体设计决定

### 1.1 主流程、数据对象、团队职责

1. 业务主线：**客户→产品/套餐→订单/订单项→开通任务→服务实例→实际出口/资源绑定→使用/续费/变更/终止**。同一客户可有多个服务，订单不是服务，订单项可产生多个服务实例。
2. 资源主线：**CentOS（管理）↔ROS（当前1:1、拨号）→家宽/线路（节点=ROS逻辑线路）→当前IP运行信息**；来源型资源池组织SHARED/LONG线路，多池成员可重叠。线路不直接拥有客户字段；由服务绑定推导关联客户。CentOS负责B/C段。
3. 外部交付：**供应商→采购套餐→反向代理→客户服务**；客户只能看到平台主管入口，不得暴露上游密钥。外部资源不进入自有来源型池。
4. 业务平台负责记录和编排；IP资源API组提供真实资源状态/操作；五产品组提供真实数据面开通、暂停、恢复、迁移、撤销与验证。UI的“执行成功”以相应真实结果为准，不能以本地写库或Mock返回冒充真实交付。
5. 产品依旧五类：短效IP、长效IP、独享IP、VPN、隧道。不恢复“产品资源策略”业务配置、不增加VPN池/隧道池。不新增充值、彩虹币、卡密、云手机、实名通过后的人工二次审核或独立内部资源故障告警。

### 1.2 页面组件与通用交互约定

| 组件或行为 | 全站规范 | 防错要求 |
|---|---|---|
| 列表 | 页面标题、业务筛选、数据表、分页、导出及批量操作（按权限出现） | 列默认不放纯技术字段；长ID可复制但不能替代业务名称；筛选支持清空/重置 |
| 详情 | **编号/名称可点击进入详情**；顶部摘要+按主题分组的子列表/标签+关联业务入口 | 展示对象来源、状态更新时间及数据是否过期；当前值和历史快照分开 |
| 创建/编辑 | 轻量字段优先弹层/抽屉；有跨对象依赖或不可逆执行的操作用独立向导 | 下拉选对象名称并带查询；自动带出只读归属，禁止人工填裸ID |
| 业务操作 | 列表快捷操作进入统一业务操作组件；复杂变更统一先预检、展示影响、再确认 | 不直接在按钮点击时执行终止、切换、发放或解除占用 |
| 表单校验 | 必填/格式/范围/单位/唯一性/关联归属/对象启停/时间交集 | 提交时服务端重验，不信赖预览快照；出错展示业务原因和下一步 |
| 状态 | **业务状态、资源上报状态、外部适配执行状态、探测状态分离** | 仅管理面成功显示“待真实交付确认”；过期数据标UNKNOWN而非在线 |
| 关联详情 | 客户↔服务↔订单项↔资源绑定；线路↔ROS↔CentOS↔池；采购↔代理↔服务 | 子列表均可跳转，保留父页面上下文和返回路径 |
| 安全 | 上游密码/密钥/Webhook默认掩码；一次性新凭证限权展示；高影响操作记审计 | 导出/日志不含明文Token/Secret；不以竞品的明文列表为模板 |
| 成功/失败 | 显示业务编号、完成状态、成功/失败数量、实际绑定/入口与失败原因 | 不返回调试JSON给运营人员；远端执行中展示进度并可重试/回查 |
| 失效引用 | 被服务/订单/监控引用的对象，停用前展示受影响列表 | 禁止无确认物理删除；优先逻辑停用，保留历史 |
| 日期与统计 | 统一时间范围、时区、指标定义、更新时间；前台转换秒/分钟/天/Byte等 | “当前IP数”“去重IP数”“历史新IP数”“提取量”“实际流量”禁止混为同一指标 |

### 1.3 布局/路径统一

- **统一客户/服务工作区**：点击客户、订单、服务名称或编号，进入对象详情；从子表跳转时应可返回原位置。服务详情是运营处理续费、切换、解绑、监控与审计的业务枢纽。
- **列表展示列与表单字段不等价**：竞品提供了丰富运营字段，但其中的客户归属、BAS汇总、实时IP等可能是关联/派生字段，不得盲目存到错误主表。
- **主子表必须同时设计**：订单主表+订单项；资源池+成员线路/引用；服务+资源绑定/出口授权/凭证/变更/执行任务；供应商+采购；采购+代理；监控规则+检测对象/通知记录；备用关系+切换任务及日志。
- 正式原型当前已有独立详情页与部分列表；本稿提出的抽屉/分区仅为新功能交互建议，**不擅自推翻已确认页面导航风格**。精确路由与尺寸在第三轮原型更新时确定。

## 3. 主子表与跨模块引用，不得遗漏

| 主对象 | 必须有的子表/关联区 | 来源/权限与禁止事项 |
|---|---|---|
| 客户 | 认证记录、客户账号、订单、服务、凭证摘要、使用统计、长效告警 | 从实际模块查询，客户详情不生成孤立副本 |
| CentOS | 对应ROS、关联线路、运行指标、操作日志 | B/C段聚合归CentOS，不修改源ROS管理边界 |
| ROS | 家宽/线路、BAS汇总、拨号/上报日志 | 无所属CentOS冗余列表列、无ROS主备配置 |
| 家宽/线路 | 所属ROS/CentOS、当前IP/端口、域名、池成员、关联服务绑定、拨号/IP变化、备选引用 | 不新增直连customer_id；关联客户由服务绑定推导 |
| 资源池 | 成员线路、共享/长效统计、服务使用引用、成员变更日志 | 不是五产品类型池；允许一线多池 |
| 套餐 | 产品、业务权益、宽限规则、现有服务使用数、修改影响 | 价格和宽限规则更新不静默改历史服务快照 |
| 订单 | **订单项**、开通/变更任务、生成服务、操作日志 | 新购与续费/扩容/变更不能混成生成新服务 |
| 服务 | 订单项引用、交付摘要、资源绑定、出口授权、备用候选、切换任务、凭证、变更、到期/释放任务、日志/告警 | 客户与资源关系的唯一业务入口，历史完整 |
| 供应商 | 采购套餐、接口连接测试和变更日志 | 凭证加密、脱敏 |
| 采购套餐 | 反向代理、关联客户/服务、上游期限/配额、续购和健康日志 | 禁止未经预检缩短到期影响活跃服务 |
| 反向代理 | 采购引用、客户/服务、平台代理入口、适配执行记录、停用/解绑任务 | 上游源密码不直接展示；关闭服务不自动取消采购 |
| 监控配置 | 目标代理、客户机器人、告警和通知历史 | 不能跨客户引用机器人 |
| 切换/交付任务 | 每次尝试、回执、探测、错误、补偿、审计 | 数据面未确认时不得报告业务成功 |

## 4. 设计优先级、冻结范围与验收门槛

- **P0一期先评审**：UI-11/12/13/16/17/19/21/23/24/25/26。这些页面涉及出口独享承诺、固定IP/宽限时效及跨系统资源真实控制，设计未确认不得直接进入大规模并行编码。
- **P1完善后评审**：其余相关模块的字段与互动，提高可追溯性和运营可用性；通用状态、角色权限、详情跳转、操作失败反馈应统一一次实现。
- **P2不扩大范围**：竞品卡密、充值、云手机、内容运营与其他未经确认业务不新增；竞品页面字段要按原有实体所有权和数据来源过滤。
