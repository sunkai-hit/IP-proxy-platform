# V1.2｜第二轮补充：36项页面字段级与交互契约检查表

> 状态：2026-10-14，第二轮设计评审补充稿；不是正式需求、数据库DDL、已实现API或已验收页面。  
> 基线：正式V1.2 Word、第一轮P0设计、第二轮三份设计稿、彩虹代理竞品调研报告与用户业务确认。  
> 用途：将第二轮“应该显示哪些字段”落实为“查询→列表→详情/子表→创建/修改→预检→执行结果”的逐页检查表。字段编码、长度、精确权限码、API路径和数据来源的技术实现需第三轮确认。

## A. 本轮不能改动的已确认口径

- [确认] 独享按**实际交付的公网出口IPv4**跨客户排他。不同来源线路/端口/资源池不能绕过排他；同客户多服务是否允许复用尚待业务决定。
- [确认] 长效IP长期固定、可多客户共享；独享IP固定且不能给**其他客户**共享出口。固定出口IPv4与线路当前上报IP是两个字段。
- [确认] 长效与独享**按具体套餐**配置宽限天数；到期先停服、固定出口在宽限期保留，真实恢复后才重新标为可用。宽限默认、0天是否允许、新期起算点未确认。
- [确认] 只设计**服务上下文中的人工主备切换**，不能恢复ROS设备级自动切换及策略编辑；ROS只负责拨号，实际切换需资源API与具体产品数据面能力配合。
- [确认] CentOS↔ROS目前1:1，家宽/线路=节点=ROS逻辑线路，池按省市运营商等来源属性聚合SHARED/LONG线路；线路客户从服务绑定推导，不能直接赋予客户。
- [确认] 客户→订单/订单项→开通任务→服务实例→资源绑定→实际交付/生命周期；订单为主、特权直接开通和直接调整保留。外部供应商→采购套餐→反向代理→服务独立交付链。
- [确认] 不纳入充值、彩虹币、卡密、云手机、内容/资讯、实名通过后人工二次审核、新的内部资源故障通知模块。
- [设计要求] 竞品证据大多为页面观察，以下设计是**我方方案**，不能宣传为竞品真实操作已验证，也不能把Mock成功称为真实交付。

|统计口径|总数/在线数/去重IPv4/历史新增IP及分子分母|定义明确、统一时间范围和采样点|跨池多重成员去重；不同业务指标不能直接加总|

### 统一交互验收

列表支持组合筛选、重置、分页、明确空态、数据刷新时间；可导出的页面按权限与脱敏规则执行。详情采用“顶部主记录摘要 + 业务子表 + 历史/任务/审计”，跨页跳转返回原列表筛选。新建/编辑使用业务选择器并带出只读归属，删除引用对象前展示影响；高风险操作必须走“预检→差异/影响→确认原因→执行进度→真实结果”，不能只弹“确定吗”。保存失败保留已输入且非敏感内容，失败原因可处理，异步任务可重新打开回查；不以原始JSON作为运营反馈。

## D. 动作级拦截与成功判定（研发必须据此设计）

|动作|提交前必须校验|真正成功的判断与失败补偿|
|---|---|---|
|新购开通|订单NEW及状态、订单项/实例归属、套餐能力、出口跨客户独享冲突、自有池/外部采购授权与期限、数据面适配可用|逐实例真实交付回执+入口验证；成功/失败分计；幂等回查与异常补偿|
|特权直接开通|独立权限、客户/产品/套餐有效、原因、与普通开通同样的容量/冲突/适配预检|真实开通与服务实例回写；在审计中标明“手工渠道”|
|套餐调整|周期/金额/权益单位、适用产品、是否改变在用服务、宽限快照|仅未来新服务采用新版本；既有服务必须走授权变更而非静默改写|
|人工主备切换|服务/主出口/备选归属、在线与固定IP能力、出口排他、入口及监控影响、权限与原因|资源和数据面实际切换+连通验证，之后才切换主绑定；失败保持可追溯旧占用，创建补偿任务|
|服务续费|订单或特权渠道、原到期/宽限、续费起算口径待确认、上游采购覆盖、续期凭证有效性|真实恢复（如原已停服）及新期限生效后成功；回执不明则异步追踪而不提前标ACTIVE|
|服务暂停/到期停服|服务状态、资源/凭证/平台代理实际访问能力及可执行适配器|客户端真实无法访问，保留占用到约定截止；禁止误释放固定出口|
|服务终止/超宽限释放|未结任务、客户与服务引用、外部代理解绑、出口排他记录与实际资源占用|真实禁用/撤销/释放确认后解除引用与出口锁；失败置待恢复/重试队列|
|外部采购调整/代理停用|采购授权范围、上游到期、当前关联有效客户服务与真实绑定|真实适配器停止/解绑，回执与服务影响可追踪；采购保留、服务与代理解绑分开|
|域名同步/凭证重置|业务归属、真实接口能力、目标解析/入口影响、独立权限与原因|收到真实回执并验证；新凭证仅受控一次展示，失败不得声称已同步/更新|

## E. 第二轮设计质量门槛与第三轮输入

**设计阶段可验收**：36个页面/功能组均能明确定位到“查询字段、列表字段、详情主子关系、允许操作、禁用原因、状态与审计”；11类日志和7类统计不删减；P0覆盖独享出口、套餐宽限、人工切换、外部代理、开通/续费/停服/释放。与第一轮既定32场景互相引用，不以原型漂亮替代业务闭环。

**本轮不得宣称已实施**：正式Word/交互原型/接口/数据库/实际数据面未因本文生成而更新；竞品按钮可见不代表竞品写操作验证通过。下一轮须用本表逐项生成原型检查点、字段类型/必填/校验/API映射、精确权限码与自动化验收用例。

**仍待业务/接口决定，不可默认填值**：
1. 同一客户多独享服务能否复用同一公网IPv4、额度怎么计数。
2. 长效/独享套餐宽限默认值、是否允许0、新周期从旧到期还是续费执行时起算，存量服务如何迁移。
3. 资源API稳定线路来源ID、固定IP真实保证、切换跨ROS/CentOS支持及真实执行方。
4. 外部采购是否允许多客户授权复用及采购过期后的客户服务处理界限。
5. 出口全局排他锁、操作幂等、补偿任务的精确数据模型与权限码。
