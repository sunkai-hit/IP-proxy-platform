# V1.2-R3｜尚未确定的业务规则决策单（需要业务负责人批准）

依据：第一轮Q01—Q08、第二轮P0/P1页面字段及用户已经批准的三原则。日期：2026-10-14。
**以下“推荐”不是用户确认，不得把推荐写成已经生效的生产规则。** 未确认时采用阻断/不可销售/不改变存量权益的保守处理。

## 已批准并无须重复提问
- 独享公网出口IPv4跨客户排他，端口、线路、池不同亦不能复用给其他客户。
- 长效、独享套餐分别配置续费宽限天数，到期立即停服并保留固定出口至约定截止。
- 只做服务级**人工主备切换**，ROS不恢复设备级自动主备和配置入口。

## 请业务负责人最终确定的项目

|编号|业务问题|推荐处理（待批准）|现在的安全过渡|
|---|---|---|---|
|BIZ-01|同一客户多个独享服务能否复用相同公网IPv4？如何计算“IP数量”|**第一版本建议一个独享IPv4最多归属同客户一个服务实例**；若以后开放同客户复用，按客户去重IPv4计数并增加明确授权关系，不随意重复计费|已按“不同服务同IPv4先阻断”，不把该更严策略当作已批准|
|BIZ-02|套餐宽限默认值、允许0天吗？|建议**无系统默认**，在长效/独享上架前要求明确填写；0天表示没有宽限，需要显式风险确认后才可上架|后端要求非负整数，未配置不允许新开通；上架是否允许0仍待决定|
|BIZ-03|宽限内续费新有效期从何时起算？|建议**宽限内从原业务到期时刻顺延**，使连续固定出口保留有一致口径；超宽限须走重新开通并以实际交付时刻起算|旧代码按当前时间计算已过期续费不满足确认口径，R3旧变更入口已拦截待确认场景|

## 仍是技术组签收，不需要业务负责人决定实现细节
- TECH-01：IP资源API提供稳定来源ID、IPv4能力证明、跨ROS/CentOS真实切换支持范围和失败补偿。
- TECH-02：产品组提供对真实数据面的开通/停服/恢复/续费/终止、出口验证、流量统计和幂等查单。
- TECH-03：技术组决定全局IPv4锁、数据迁移、操作任务/Saga状态、真实回执证据、日志/权限实现；不得改变BIZ已批准的用户承诺。

## 需要签收前不能做的事
不要把“允许0天”“续费从当前时刻起算”“同客户独享复用”“外部采购跨客户共享”“人工切换可以变更承诺固定IP”当成业务事实；不要在旧占用未经核对时回填或解锁公网IPv4。以上待确定事项的批准记录必须同步正式Word、交互原型、ER/API契约和可复现的验收场景。
